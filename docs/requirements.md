# RAGシステム 要件定義書

**プロジェクト名**: サークル書類・マニュアル RAGシステム  
**作成日**: 2026-06-12  
**技術責任者**: 複数人体制

---

## 1. 概要・目的

サークルの書類・マニュアルに対して、チャットで自然言語質問ができるRAGシステム。ハルシネーションを抑制し、出典（PDF名・ページ）を明示することで、利用者が信頼できる回答を得られる仕組みを構築する。

---

## 2. 利用者と利用シーン

- **対象**: サークル員 10〜50人（段階的に利用拡大）
- **接続方法**: Tailscale または大学VPN経由（ポート開放なし）
- **初期段階**: 月間クエリ量は多くない想定（広めながら増加）

---

## 3. 機能要件

### 3.1 コア機能

| 機能 | 説明 |
|------|------|
| PDFアップロード | 管理者が書類・マニュアルをPDFで追加 |
| テキスト検索 | Chromaを用いたベクトル検索で関連箇所を抽出 |
| 質問応答 | Gemini APIで質問に回答 |
| 出典表示 | 回答に「PDF名・ページ番号」を明示 |
| インデックス再構築 | PDF追加後、管理者が手作業で再インデックス |

### 3.2 Webインターフェース

- 既存の認証・Web基盤を再利用（仲間が構築済み）
- 詳細はそのシステムに合わせて実装

---

## 4. 非機能要件

| 項目 | 要件 |
|------|------|
| **ハルシネーション抑止** | 検索結果の範囲内で回答するよう指示 |
| **プライバシー** | PDF全文はラズパイ内に保持、APIには質問+検索断片のみ送信 |
| **可用性** | ラズパイで常時稼働（電力実質無料） |
| **バックアップ** | Chroma/PDFは定期バックアップ（SDカード破損対策） |
| **応答性** | 初期段階では高速化は優先度低 |

---

## 5. システム構成

### 5.1 配置

```
┌─────────────────────────────────────────────────┐
│  利用者（学内外）                                 │
│  (Tailscale / 大学VPN)                          │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  ラズパイ（部室内）                               │
├─ Webインターフェース                             │
├─ Chroma（ベクトル化・検索）                      │
├─ PDF管理                                       │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  外部API                                       │
├─ Gemini API（生成）                            │
├─ Embedding API（ベクトル化）                    │
└─────────────────────────────────────────────────┘
```

### 5.2 技術スタック（確定分）

| 層 | 技術 | 理由 |
|------|------|------|
| **フロントエンド** | React + TypeScript (Vite) | 主流、保守性高い |
| **バックエンド** | Python FastAPI + uvicorn | 軽量、モダン、RAG向き |
| **ベクトル DB** | Chroma（ファイルベース） | 軽量、ラズパイ対応 |
| **Embedding モデル** | sentence-transformers (all-MiniLM-L6-v2) | 無料、軽量（90MB）、日本語対応 |
| **生成 API** | Gemini API（無料枠） | 低コスト、精度高い |
| **ローカル DB** | SQLite | 軽量、ラズパイ対応 |
| **ホスト** | ラズパイ | 常時稼働、電力実質無料 |

## 6. 制約条件

| 制約 | 詳細 |
|------|------|
| **コスト** | 基本無料、クレジット枠は相談ベース |
| **PDF更新** | 手作業で新版に切り替え（自動化は将来） |
| **インデックス再構築** | 管理者がスクリプト実行（自動化は将来） |
| **ポート開放** | なし（Tailscale/VPN経由のみ） |

---

## 7. 実装方針

### 7.1 スコープ（Phase 1 優先）

**今すぐ実装**：
- PDFの取り込みと前処理
- Chromaへのインデックス構築
- Gemini APIを用いたQAパイプライン
- 出典追跡ロジック
- 再インデックススクリプト
- ターミナル CLI / Jupyter で実験可能な状態

**後回し（Phase 2）**：
- Webインターフェース（FastAPI + React）
- 認証・セッション管理

### 7.2 設計の優先順位

1. **実験効率**: ターミナル/Jupyter で高速に回せる
2. **正確性**: 出典が明確で、ハルシネーションが少ない
3. **シンプルさ**: メンテナンス性を重視
